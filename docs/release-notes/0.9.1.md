## Was 0.9.1 bringt

- **Legende und Achsenbeschriftung berühren sich nicht mehr.** Die Legenzeile des Diagramms bekam in einem schmalen Fenster keinen Platz und zeichnete über die Zeitachse; das Achsenband und der Ereignisprotokoll-Kopf bekommen jetzt fest reservierten Platz (`PLOT_BOTTOM_H`).
- **Die Zeitachse sagt wieder, was sie meint.** Ein Fenster, das weiter zurückreicht als die Sitzung läuft — direkt nach dem Start, oder jederzeit bei 24 h — zeigte auf *jedem* Tick „00:00“. Positionen vor dem Sitzungsbeginn heißen jetzt „-00:25“.
- **Die Millisekunden-Linien folgen der Skala.** Vier feste Werte (30/80/150/300 ms) lagen auf einer Skala von 1400 ms dicht übereinander und ihre Zahlen standen aufeinander. Der Abstand kommt jetzt aus der Skala (`ms_band_step`).
- **Zweite Zeile einer Zielzeile** läuft nicht mehr unter dem Wert der Zeile; der Textplatz wird an der gemessenen Breite des Wertes begrenzt und bei Bedarf abgekürzt.
- **Neuer Regressionstest** `app/tests/layout.rs`: malt die Oberfläche bei vier Fenstergrößen und liest jede gesetzte Textposition aus eguis Zeichliste zurück — kein Text auf Text, kein Text außerhalb des Fensters, und keine Achsenzeile, die sich selbst wiederholt. An den Rechtecken der Widgets allein ist das nicht zu erkennen — sie sagen nichts über Text, der *außerhalb* von ihnen gemalt wird.
- Ein Test, der die Live-Schleife wirklich messen lässt, sagt jetzt Bescheid, wenn das Firewall-Verhalten des Rechners ihn unmöglich macht, statt eine kaputte Messstrecke zu melden.
- **Die Dateien für Windows und Linux kommen jetzt aus der Werkstatt, nicht vom Schreibtisch.** `.github/workflows/release.yml` baut auf `windows-latest`, `ubuntu-latest` und `macos-latest` und hängt alles an den Release; `.github/workflows/ci.yml` läuft bei jedem Push auf allen drei Systemen (Format, Clippy, Tests, ein gemalter Rahmen als Rauchtest).

## Herunterladen

Die Dateien entstehen auf GitHub Actions, je System auf dem laufenden Runner — Windows auf
`windows-latest`, Linux auf `ubuntu-latest`, macOS auf `macos-latest` (siehe
`.github/workflows/release.yml`). Jede Datei ist bei ihrer Entstehung geprüft: der Build malt vor
dem Verpacken einen Rahmen (`--shot`), auf Linux unter Xvfb.

| Datei | System | Inhalt |
| --- | --- | --- |
| `System-Ping-0.9.1-macos-arm64.zip` | macOS, Apple Silicon | `System-Ping.app` — Doppelklick startet ohne Terminal-Fenster |
| `system-ping-0.9.1-macos-arm64.tar.gz` | macOS, Apple Silicon | dieselbe Programmdatei ohne Bundle, für die Befehlszeile (`--help`) |
| `System-Ping-0.9.1-windows-x64.zip` | Windows 10/11, 64 Bit | `System-Ping.exe` (Datei-Symbol und Versionsangaben stecken in der Datei), `icon.ico`, README |
| `system-ping-0.9.1-linux-x64.tar.gz` | Linux, x86_64 | die Programmdatei für die Befehlszeile, README |
| `SHA256SUMS.txt` | — | Prüfsummen aller Dateien, eine Liste für den ganzen Release |

**macOS.** Die beiden Dateien sind **ad-hoc signiert** (`codesign -s -`), nicht von einem
Apple-Entwickler-Zertifikat und nicht notarisiert. Ein Download aus dem Netz bekommt deshalb von
macOS das Quarantäne-Attest, und das ist bei einer nicht notarisierten Datei unerwartet streng:

1. `System-Ping.app` **erst nach `/Applications` verschieben** und von dort starten. Eine quarantänebehaftete App, die aus dem Download-Ordner heraus gestartet wird, verlagert macOS in einen zufälligen, schreibgeschützten Ort (App-Translocation) — dann liegt der Zustand zwar weiterhin in `~/Library/Application Support/system-ping`, aber die App, die man sieht, ist nicht die Datei, die man angefasst hat.
2. Beim ersten Start kann macOS melden, die App könne „wegen nicht verifizierter Herausgeber nicht geöffnet werden". Dann hilft Sekundärklick (rechtster Mausklick) → „Öffnen".
3. Wird dieser Ausweg nicht angeboten, nimmt die Quarantäne der Befehl:
   ```sh
   xattr -dr com.apple.quarantine /Applications/System-Ping.app
   ```
4. Dasselbe gilt für die einzelne Programmdatei, wenn sie über den Browser heruntergeladen wurde: aus dem Terminal heraus wird eine quarantänebehaftete Datei beim Start vom System beendet (Exit 137, im Terminal als „killed" zu sehen). Vor dem ersten Lauf:
   ```sh
   xattr -d com.apple.quarantine system-ping-0.9.1-macos-arm64
   ```
   Mit `curl` heruntergeladene Dateien bekommen kein Quarantäne-Attest und laufen ohne diesen Schritt.

Nach dem ersten Öffnen ist die Markierung erledigt; ein späteres Aktualisieren behält Ziele,
Historie und Fensterplatz, weil beides — Bundle und Programmdatei — denselben Zustandsordner
benutzt (`~/Library/Application Support/system-ping`).

**Windows.** `System-Ping.exe` ist mit dem MSVC-Toolkit gebaut und braucht die Visual-C++-Laufzeit,
die auf einem aktuellen Windows ohnehin fast immer vorhanden ist. Die Datei liegt portabel: der
Zustandsordner mit Zielen, Historie und Fensterplatz entsteht neben ihr. Der Autostart-Eintrag
(Einstellungen → „Beim Anmelden starten") schreibt in `HKCU\...\Run`. Virenschützer können nach dem
ersten Start einer frisch heruntergeladenen `.exe` fragen — das ist bei einer Datei ohne
Herkemarks-Information aus dem Netz normal, nicht ungewöhnlich für dieses Programm.

**Linux.** Gebaut auf Ubuntu 24.04 (x86_64) gegen die Systembibliotheken, wie der README es
beschreibt: X11- und Wayland-Bindungen werden zur Laufzeit geladen, OpenGL über EGL/GLX. Auf einer
Desktop-Installation sind diese Bibliotheken da. Läuft das Programm trotzdem nicht, fehlen sie —
dann helfen die Laufzeitpakete der Build-Anleitung im README:

```sh
sudo apt install libgl1 libx11-6 libxcursor1 libxi6 libxinerama1 libxrandr2 libxkbcommon0
```

Der Zustandsordner ist `~/.local/share/system-ping` (oder `$XDG_DATA_HOME/system-ping`). Der
Datei-Dialog läuft über das Freedesktop-Portal, braucht also kein GTK. Eine `.desktop`-Datei oder
ein AppImage wird nicht mitgeliefert — bitte die Datei ausführbar machen (`chmod +x`) und starten;
der Autostart ist auf Linux bewusst nicht umgesetzt.

## Downloads (English)

All files are built on GitHub Actions, one runner per operating system, and each one paints a
frame before it is packed (`--shot`), so an artefact that cannot open a window never reaches the
release.

| File | System | Contents |
| --- | --- | --- |
| `System-Ping-0.9.1-macos-arm64.zip` | macOS, Apple Silicon | `System-Ping.app` — double click, no terminal window |
| `system-ping-0.9.1-macos-arm64.tar.gz` | macOS, Apple Silicon | the same program file without a bundle, for the command line (`--help`) |
| `System-Ping-0.9.1-windows-x64.zip` | Windows 10/11, 64-bit | `System-Ping.exe` (file icon and version info embedded), `icon.ico`, readme |
| `system-ping-0.9.1-linux-x64.tar.gz` | Linux, x86_64 | the program file for the command line, readme |
| `SHA256SUMS.txt` | — | checksums of every file, one list for the whole release |

**macOS.** The two files are **ad-hoc signed**, not notarized, so macOS treats a download as
untrusted: move `System-Ping.app` to `/Applications` before the first start (a quarantined app
launched from the Downloads folder gets relocated to a random read-only place), and if the system
refuses to open it use right click → Open, or
`xattr -dr com.apple.quarantine /Applications/System-Ping.app`. The bare binary needs the same once
(`xattr -d com.apple.quarantine <file>`) — a quarantined file run from a shell is killed by the
system.

**Windows.** Built with the MSVC toolchain, so the Visual C++ runtime is required; a current
Windows has it. The file is portable: targets, history and window place are stored next to it.

**Linux.** Built on Ubuntu 24.04 (x86_64) against the system libraries — X11 and Wayland bindings
are loaded at run time, OpenGL through EGL/GLX. A desktop install has them already; if the file
does not start, install the runtime packages listed in the README's build section
(`libgl1 libx11-6 libxcursor1 libxi6 libxinerama1 libxrandr2 libxkbcommon0`). State goes to
`~/.local/share/system-ping`, the save dialog uses the freedesktop portal (no GTK needed). No
`.desktop` file and no AppImage: `chmod +x` and run it.
